Убрать лишний домен demo.alsn.ru из поиска

Дата: 15.09.2026. Цель: снять диагностику Яндекса TOO_MANY_DOMAINS_ON_SEARCH и убрать дефолтную страницу IIS из выдачи. Это не Тильда и не основной alsn.ru — отдельный сервер (IIS) на поддомене.

Лишний хост в поиске robots.txt уже закрыт Нужно удаление в Вебмастере Не трогать alsn.ru
Что сейчас (проверка 15.09.2026)
В Яндексе по запросу site:demo.alsn.ru — 1 результат: «IIS Windows Server». Сайт живой (ответ 200). Файл https://demo.alsn.ru/robots.txt уже запрещает весь хост (Disallow: /). Значит закрытие роботом сделано, а страница из индекса ещё не вычищена — нужен шаг удаления в Вебмастере (и желательно усилить ответ сервера).
Шаги
  1. Проверить robots.txt
  2. Добавить demo.alsn.ru в Яндекс.Вебмастер
  3. Удалить из поиска префиксом
  4. Усилить закрытие на IIS (желательно)
  5. Как проверить через 3–14 дней
Не делать
  • Не менять robots.txt на основном alsn.ru (Тильда его не даёт править).
  • Не удалять из поиска префикс https://alsn.ru/ — снесёте основной сайт.
  • Не путать с почтой mail.alsn.ru — её не трогаем.
Шаг 1

Проверить robots.txt

Что сделать. Убедиться, что поддомен закрыт для роботов.

Зачем. Без запрета удаление из поиска Яндекс может снова вернуть страницу.

  1. Откройте в браузере: https://demo.alsn.ru/robots.txt
  2. Должны быть строки Disallow: / для User-Agent: * и для Яндекса.
  3. Если файла нет или он пустой — выложите на корень IIS файл ниже (путь обычно C:\inetpub\wwwroot\robots.txt или корень сайта demo в IIS).

Готовый текст (уже лежит в репозитории seo-data/robots-subdomains/robots.txt):

User-Agent: * Disallow: / User-Agent: Yandex Disallow: / User-Agent: Googlebot Disallow: /
На 15.09.2026 файл на demo уже открывается с этим содержимым — шаг можно отметить «проверено» и идти к удалению в Вебмастере.
Шаг 2

Добавить demo.alsn.ru в Яндекс.Вебмастер

Что сделать. Подключить поддомен как отдельный сайт в том же аккаунте Вебмастера, где уже есть alsn.ru.

Зачем. Удалять чужой хост из поиска можно только после подтверждения прав на него. С основного alsn.ru «кнопкой» demo не вычистить.

  1. Откройте webmaster.yandex.ru под аккаунтом сайта.
  2. «Добавить сайт» → укажите https://demo.alsn.ru (лучше именно HTTPS).
  3. Подтвердите права удобным способом (HTML-файл в корень IIS, meta-тег или DNS TXT — что проще для вашего сервера).
  4. Дождитесь статуса «Права подтверждены».
https://demo.alsn.ru

Справка Яндекса: быстрый старт, поддомены.

Шаг 3 — главный

Удалить из поиска префиксом

Что сделать. Попросить Яндекс убрать из выдачи весь поддомен.

Зачем. Одна страница «IIS Windows Server» уже в индексе; robots сам по себе чистит медленно. Префиксное удаление ускоряет выход из поиска и помогает снять TOO_MANY_DOMAINS_ON_SEARCH на основном alsn.ru.

  1. В Вебмастере откройте сайт https://demo.alsn.ru (не alsn.ru).
  2. Раздел вроде «Индексирование» → «Удаление страниц из поиска» (или «Инструменты» → удаление).
  3. Тип: удаление по префиксу / адресу сайта.
  4. Вставьте префикс строго так:
https://demo.alsn.ru/
  1. Отправьте заявку. Дождитесь статуса «удалено» / «обработано» (обычно от нескольких дней до ~2 недель).
  2. Если доступен ещё http://demo.alsn.ru/ без редиректа на HTTPS — отдельно удалите и его префикс:
http://demo.alsn.ru/
Квота на удаления ограничена. Не тратьте её на основной alsn.ru. Справка: удаление страниц из поиска.
Шаг 4 (желательно)

Усилить закрытие на IIS

Что сделать. Чтобы робот не цеплял дефолтную страницу даже до переобхода robots.

Зачем. Сейчас корень отдаёт 200 и HTML «IIS Windows Server» — это сигнал «живого» мусорного сайта.

Вариант A — лучший, если demo больше не нужен

  1. В IIS для сайта demo отключите дефолтную страницу / остановите сайт.
  2. Либо настройте ответ 410 Gone или 404 на все URL.
  3. Либо уберите DNS-запись demo у регистратора (после удаления из поиска).

Вариант B — demo ещё нужен сотрудникам

  1. Оставьте robots как есть.
  2. Добавьте в ответ сервера заголовок запрета индексации (web.config IIS):
<configuration> <system.webServer> <httpProtocol> <customHeaders> <add name="X-Robots-Tag" value="noindex, nofollow" /> </customHeaders> </httpProtocol> </system.webServer> </configuration>

Файл web.config — в корень сайта demo. Если файл уже есть, вставьте только блок customHeaders в существующий system.webServer.

  1. Закройте доступ снаружи паролем / VPN / firewall, если это внутренняя демка.
Шаг 5

Проверка через 3–14 дней

Что сделать. Убедиться, что Яндекс больше не показывает demo.

  1. В поиске: site:demo.alsn.ru — должно стать «ничего не найдено».
  2. В Вебмастере на alsn.ru → Диагностика: статус TOO_MANY_DOMAINS_ON_SEARCH — «отсутствует» / снят (может задержаться на дни после очистки).
  3. ИКС смотреть отдельно: отскок с 250 к 260 не гарантирован сразу, но фон риска уходит.
site:demo.alsn.ru
